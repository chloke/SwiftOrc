# Security Policy

## Supported versions

Security fixes are provided for the latest tagged release. Until the first
release is tagged, the default branch is the only supported version.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability and do not include
private user data, credentials, prompts, model output, or provider response
bodies in a report.

Use **Report a vulnerability** on the repository's **Security** tab. This sends
the report through GitHub's private vulnerability-reporting channel. Include a
concise description, affected version, reproduction steps, impact, and any
suggested mitigation.

If private vulnerability reporting is temporarily unavailable, wait for that
channel to become available rather than publishing exploit details in an issue.

The framework's application-facing security model and secure-use guidance are
documented in [Documentation/Security.md](Documentation/Security.md).
